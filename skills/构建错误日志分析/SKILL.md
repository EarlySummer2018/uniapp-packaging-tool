---
name: 构建错误日志分析
description: 当用户上传构建错误日志（如编译、测试或打包失败输出）时自动触发。分析日志内容，结合当前项目（unipack-tool）的代码和配置，定位错误原因，生成详细的修复建议文档，并以“YYYYMMDDHHMMSS-fix.md”格式命名，保存到项目根目录下的 logs/ 目录。
---

## 触发条件

- 用户在对话中上传了包含构建错误信息的文本文件（如 `.log`, `.txt`）或直接粘贴了错误输出。
- 错误内容涉及 `cargo check`、`cargo build`、`cargo test`、`cargo run` 或 Tauri 相关构建工具（如 `tauri build`）。

## 执行流程

1. **提取错误信息**  
   - 从用户上传的文件或消息中提取完整的错误输出。  
   - 保留原始错误内容，同时提取关键信息：错误类型（编译错误、链接错误、测试失败、资源缺失等）、错误位置（文件路径、行号）、错误代码（如 E0432）。

2. **分析错误原因**  
   - 根据错误类型，结合当前项目（`unipack-tool`）的结构进行上下文分析：  
     - 编译错误：检查缺失依赖、类型不匹配、未导入模块、生命周期问题等。  
     - 链接错误：检查 `Cargo.toml` 中的依赖配置、目标平台、外部库路径。  
     - 测试失败：分析断言失败原因、panic 信息、测试用例与实现逻辑的差异。  
     - Tauri 构建错误：检查 `tauri.conf.json`、资源路径、权限配置等。  
   - 搜索项目中的相关代码文件（通过 `rg` 或 `grep` 定位错误位置）。  
   - 确认错误的根本原因。

3. **生成修复文档**  
   - 创建一个 Markdown 文件，文件名格式为 `YYYYMMDDHHMMSS-fix.md`（例如 `20250602143052-fix.md`）。  
   - 文档内容结构如下：  
     ```markdown
     # 构建错误分析报告

     **生成时间**：YYYY-MM-DD HH:MM:SS  
     **错误来源**：（用户上传的文件名或直接粘贴）  

     ## 原始错误日志

     （将关键错误部分摘录于此）

     ## 错误分析

     - **错误类型**：xxx  
     - **错误位置**：xxx（文件:行号）  
     - **原因说明**：xxx  

     ## 修复方案

     1. 修改文件 `xxx`：  
        ```rust/diff
        // 修改前
        ...  
        // 修改后
        ...
        ```
     2. 更新配置 `xxx`：...
     3. 运行命令：`cargo add xxx` 或 `cargo clean` 等。

     ## 验证步骤

     执行以下命令验证修复是否生效：
     ```bash
     cargo check -p unipack-tool
     cargo test -p unipack-tool -- --nocapture
     ```

     ## 注意事项

     （如需要手动清理缓存、重启服务等）
     ```  
   - 将生成的文档保存到项目根目录的 `logs/` 目录（如不存在则自动创建）。  
   - 向用户返回文档路径和简要摘要。

4. **自动修复尝试（可选）**  
   - 如果错误类型明确且修复安全（如添加缺失导入、调整依赖版本），可询问用户是否自动应用修复。  
   - 自动修复前需备份原文件，修复后运行 `cargo check` 验证。  
   - 若修复成功，在文档中标记“已自动修复”，否则保留手动修复建议。

## 注意事项

- 确保不泄露敏感信息（如绝对路径、环境变量）。  
- 无法解析的错误应提示用户提供更多信息（如完整 `Cargo.toml`、`rustc --version` 等）。  
- 生成的文档应使用中文，代码注释或术语可保留英文。
