## 执行流程

1. **分步验证与自动修复循环**  

   **步骤 0 – cargo fmt**  
   - 执行 `cargo fmt`。  
   - 如果命令失败（例如 `rustfmt` 未安装或配置错误），输出警告并继续后续步骤，但建议用户安装 `rustfmt`。  
   - 格式化本身不会产生逻辑错误，因此无需修复循环。

   **步骤 1 – cargo check**  
   - 执行 `cargo check -p unipack-tool`  
   - 如果命令成功（退出码 0），进入步骤 2。  
   - 如果出现错误或警告：  
     - 逐条分析诊断信息。  
     - 根据 Rust 编译错误类型自动修复常见问题（如缺失导入、类型不匹配、未使用的变量/函数、生命周期错误等）。  
     - 修复后重新运行 `cargo check`，重复直到无错误且无警告（任何警告）。  
     - 若同一错误反复出现且无法自动修复，记录失败原因并跳转到“最终报告”。

   **步骤 2 – cargo test**  
   - 执行 `cargo test -p unipack-tool -- --nocapture`  
   - 如果所有测试通过，验证完成。  
   - 如果有测试失败或编译错误：  
     - 解析失败原因（断言失败、panic、编译错误等）。  
     - 尽力自动修复：  
       - 测试代码中的逻辑错误 → 根据预期行为修正断言或测试数据。  
       - 功能代码导致的失败 → 修正核心逻辑。  
       - 无法确定正确行为时，不做自动修改，向用户提问。  
     - 修复后重新运行 `cargo test`，重复直到全部通过。  
     - 若无法自动修复，停止循环并报告。

2. **最终报告**  
   - 成功：输出“✅ 验证通过（已格式化、无编译错误/警告、所有测试通过）”。  
   - 失败：输出清晰错误摘要，列出未解决的错误/警告/失败测试，并建议可能的解决方案。

## 注意事项

- **格式化先行**：确保代码风格一致，避免因格式问题干扰后续检查。  
- **自动修复**：仅修改与当前错误直接相关的代码，不进行无关重构。  
- **警告处理**：优先真正修正代码（如删除未使用的变量），必要时使用 `#[allow(...)]`。  
- **测试失败**：优先修正函数逻辑，除非错误明显在测试代码本身。  
- **回滚机制**：如果修复导致新错误，回滚最近一次修改并尝试另一种策略。  
- **变更记录**：所有修改操作需记录变更内容，以便用户审查。
